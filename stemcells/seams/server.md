# Seams in the server

Each upstream file under `apps/server/` that Stemcells changes: what we change, and why.
[`../seams.md`](../seams.md) is the index, and keeps each family's reasons
and the Hot-file budget.

A row goes in the file its first path belongs to, in path order, on one
line with no padding, so a new row changes no other line.

| File | Change | Why |
| --- | --- | --- |
| `apps/server/src/auth/McpOAuth.ts` | Imports `stemcells/upstream/mcpClients.ts` on its first line; the client `layerMcpClientAuthenticator` builds passes through `Stemcells.withoutHostedApp` (an import and two lines) | Copy Cell (below): an outside MCP client's thread links are the `t3-thread://` links Stemcells' own clients read, never upstream's through T3's hosted app. The server has no bundler to substitute `threadLinks.ts` through, so its client is cut where it is made |
| `apps/server/src/binCli.ts` | No `update` subcommand, and no `updateCommand` import | Same: `t3 update` lists T3's GitHub releases and installs one |
| `apps/server/src/cli/browser.ts` | `sudo` home falls back to `~/.stemcells` | Same, under `sudo` on Linux |
| `apps/server/src/cli/theme.ts` | Exports `publishThemeFile` and `writeDefaultTheme` | Stemcells publishes its theme and makes it a fresh server's default through the same guarded writes `t3 theme set` uses (`stemcells/upstream/theme.ts`) |
| `apps/server/src/environment/ServerEnvironment.ts` | Its descriptor says `triage: false` where it said `true` | No in-app triage (below): no client offers it |
| `apps/server/src/htmlRender/publicProxy.ts` | Exports `publicAddresses` (one word) | A web address brought into a chat's draft (`/api/stemcells/attachments/import`) reaches only what the HTML renderer's proxy lets through: the same check that every address a name resolves to is public (not this machine, its networks, link-local or a cloud's metadata address), and the checked addresses the connection is pinned to, so a rebinding name reaches nothing new (`stemcells/upstream/attachments.ts`; `attachments.contract.test.ts` pins it) |
| `apps/server/src/mcp/McpHttpServer.ts` | Imports `registerStemcellsTools` from `stemcells/upstream/mcpTools.ts` on its first line; `layer` merges `registerStemcellsTools(toolkitRegistration)` beside upstream's `layerTools`, which stays T3's alone | Our MCP tools, registered as upstream registers its own toolkits: `stemcells_peer_send` (Peers, below), an agent writing to a Cell on a linked machine behind upstream's gate for a tool that writes as its caller, and `stemcells_disk_report` (Disk on every machine), the cleanup Cell's measurement, `stemcells_standing`, Aski's room in one read, and `stemcells_arcs`, how the work with Cells is going (`stemcells/tasks/aski-forward.md`) |
| `apps/server/src/observability/EventLoopMonitor.ts` | Beside Node's delay histogram, a one-second beat times the longest gap since the last sample, counting one still open (`makeLoopGaps`); the sample reports the larger of the two (about twenty lines); `stemcells/upstream/loopGaps.contract.test.ts` reads a freeze no beat has seen | A freeze that crossed the sampler's 30-second tick could reach the sample before the histogram's timer, and the sample's reset lost it: every freeze long enough to drop clients went unreported, so no "froze for" toast explained the drop (`stemcells/tasks/checkpoint-freeze.md`). Upstream could take it whole |
| `apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.test.ts` | Expects those thresholds (167k for 200k and 650k on a 200k model; upstream's own expect 117k and 617k since #22654), and nothing else changes in it | It pins the thresholds this seam changes |
| `apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts` | `claudeAutoCompactThreshold` is imported from `stemcells/compaction/claudeWindow` (same name), and the local one goes | Same: the threshold a chat reports is where Claude compacts, the window capped at the model's context less 33,000, where upstream reports none at or above the context (below it, upstream takes 33,000 off too since #22654) |
| `apps/server/src/orchestration-v2/ProviderTurnControlService.ts` | Imports `* as Stemcells` from `stemcells/upstream/peers.ts` on its first line; a steer's text is `Stemcells.providerText(projections, input.threadId, message)`, and its `projectComposerContextForProvider` import goes | Same, for a message that steers a running turn |
| `apps/server/src/orchestration-v2/ProviderTurnStartService.ts` | Imports `* as Stemcells` from `stemcells/upstream/peers.ts` on its first line; a run's text for the provider is `Stemcells.text(projectionStore, projects, input.threadId, message)` where it was `projectComposerContextForProvider(…)`; the prompt-command handler is `Stemcells.promptCommandsOf(providerAuth, message)` where it was `providerAuth` | Peers (below): another Cell's message reaches the provider framed, not as the person's words, a turn's start says who's here when that changed, and only the person's own `/logout` signs a provider out. Any T3 user would want the frame and the guard; offered upstream once we ask |
| `apps/server/src/orchestration-v2/ProviderTurnStartService.ts` (resume) | Imports `resumeWithTranscript` from `stemcells/upstream/claudeAccounts.ts` on its second line; a thread resumes through `resumeWithTranscript({ session, fileSystem, path })({…})` where it was `session.resumeThread({…})` | Claude accounts (below): the transcript is in the account's folder before upstream resumes, and a copy that fails falls back to upstream's handoff |
| `apps/server/src/orchestration-v2/ThreadManagementService.ts` | Imports `moveCellsOffAskisInstance` and `refuseAskisInstance` from `stemcells/upstream/askiInstance`; `dispatch` passes each command through the first before its gate and the orchestrator; `assertProviderInstanceEnabled` (the gate every thread start and every message asks) also runs the second, takes an optional `threadId`, and the message gate passes its thread; `ThreadManagementProviderInstanceDisabledError` takes an optional `reason` its message reads | Aski's instance runs only Aski (below): the server refuses a Cell started there, rather than trusting Aski's instructions, and a message to a Cell already there runs on the driver's own instance |
| `apps/server/src/os-jank.ts` | Server base dir `~/.stemcells` | Same, for the server and CLI |
| `apps/server/src/provider/CodexAuthCallbackPage.ts` | The sign-in page's wordmark is `<strong>T3 Code</strong>`, where it bolded "T3" alone | The name transform renames whole words only: drawn as one, the build says Stemcells there (The app's name, below) |
| `apps/server/src/provider/Drivers/ClaudeDriver.ts` | Imports `stemcells/compaction/claudeWindow`; the adapter gets `withCompactWindow(config)`. Imports `stemcells/upstream/claudeAccounts`; the continuation key is `claudeContinuationKey(<upstream's key>, …)` (one statement) | The auto-compact window (below): a Claude instance that names no window hands 500k at launch. Claude accounts (below): every plain-login instance shares one key, so upstream resumes a thread in place when it moves between accounts |
| `apps/server/src/provider/ProviderOrchestrationAdapterInfrastructure.ts` | Imports `withPromptSuggestions` from `stemcells/upstream/claudeSuggestions.ts` on its first line; the Claude query runner in `layer` is `withPromptSuggestions(ClaudeAdapterV2.layerQueryRunner)` (two lines) | What to say next (below): every Claude query asks for Claude's own next-prompt suggestion and hands it to ours, where `ClaudeAdapterV2.ts`, one of upstream's hottest files, would have taken three seams; the adapter never sees the message |
| `apps/server/src/provider/agentContextBudget.json` | Holds the bytes Claude's system append and Codex's added context measure with our instructions in them (two numbers) | Upstream's `AgentContextBudget.test.ts` pins the context its agents get to this file, and our close-out, our forms and Aski's words add to it (`packages/provider-core/src/server/stemcells/`). A sync takes upstream's, runs that test and writes its measured numbers here (`generate-context-budget.mjs`) |
| `apps/server/src/server.ts` | Imports `stemcells/layer.ts` and adds its layer to `layerMakeRoutes` | Mounts all of Stemcells' server layer: Settings › Disk's `/api/stemcells/disk` routes, and the theme published on start |
| `apps/server/src/server.ts` (analytics) | Provides `Stemcells.analytics` where it provided `AnalyticsService.layer`, and drops that import | No telemetry (below): the server records through a service that keeps nothing |
| `apps/server/src/server.ts` (direct endpoints) | Provides `Stemcells.directEndpoints(DirectEndpoints.make)` where it provided `DirectEndpoints.layer` | Phones learn the Tailscale address (below): while phones over Tailscale are on, every client is told this computer's Tailscale address, without upstream's switch and its relaunch |
| `apps/server/src/server.ts` (model list) | Provides `Stemcells.modelList` where it provided `ModelManifest.layerModelCatalog` over `ModelManifest.layer`, and drops that import | No model list from T3 (below): the server runs the list bundled at build time and never asks T3's GitHub repository for one |
| `apps/server/src/server.ts` (triage) | Provides `Stemcells.triage` where it provided `TriageService.layer` over `GitVcsDriver.layer`, and drops the `TriageService` import | No in-app triage (below): a call that asks prepares nothing and reaches no git |
| `apps/server/src/serverRuntimeStartup.test.ts` | The bootstrap test's thread service and launcher die if called, and the unused `CommandId` import goes | It pins that seam: a starter thread looked for or launched fails it |
| `apps/server/src/serverRuntimeStartup.ts` | The boot heartbeat no longer records the install's owners, and drops the `getServerOwners` import | Same: naming them read the Codex and Claude login files and the T3 Connect account on every start |
| `apps/server/src/serverRuntimeStartup.ts` (welcome) | Imports `launchesStarterThread` from `stemcells/upstream/welcome.ts`; while it is false, the cwd's project is bootstrapped and the welcome names it alone, without launching a starter thread or looking for one | A server started in a folder (web mode, `pnpm dev`) sent the page to an empty thread that looked like a new Cell, but as a thread its composer read no words: a message naming places went into the folder as written. The app opens on Aski and a new Cell instead |
| `apps/server/src/telemetry/AnalyticsService.ts` | No default PostHog key or host, and telemetry off unless `T3CODE_TELEMETRY_ENABLED` turns it on | Same: no build carries T3's endpoint or key, and upstream's service, if a sync wired it back, has nowhere to send |
| `apps/server/src/textGeneration/ClaudeTextGeneration.ts` | A `runLean` call also passes `--setting-sources ""` and `--no-session-persistence` | The planner runs lean, as the Swift app's split did: no settings files, no session saved for each plan; upstream's own operations are unchanged |
| `apps/server/src/textGeneration/CodexTextGeneration.ts` | A `runLean` call also passes `--ignore-user-config` and `--ignore-rules` | The closest Codex has to Claude's lean call: no `config.toml` and no rules files (it already runs `--ephemeral`, saving no session). | `apps/server/vite.config.ts` | Imports `upstreamNamePlugin` from `stemcells/brand/nameTransform.ts` and adds it to `pack.plugins` | The name transform (The app's name, below): the server's bundle says Stemcells where upstream's code says T3 Code |
